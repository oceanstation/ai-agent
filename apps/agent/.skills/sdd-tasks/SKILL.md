# SDD · tasks 阶段

## 前置条件
- 该 feature 的 `plan` 已被用户显式批准。
- 使用本 skill 前必须先 `sdd_read_artifact(featureId)` 一次性拉回 specify + plan 全部内容。

## 目标
把 plan 里的架构决策与关键文件清单拆成**不超过 6 条**可独立勾选的任务，让 implement 阶段可以按序推进。任务数量硬上限为 6：宁可把相关工作合并进同一条任务，也不要拆出第 7 条。

## 产出格式

```markdown
# <feature> · 任务清单

> 完成一条勾一条；同批可并行的任务用同一编号前缀（如 T1.a / T1.b）。

## 任务列表
- [ ] T1 <一句话任务标题>
  - 输入：来自 plan 的哪个决策 / 哪个文件
  - 产出：具体的代码 / 配置 / 测试
  - 验收：如何证明这条任务完成（跑什么命令、看什么现象）
- [ ] T2 ...
- [ ] Tn ...

## 依赖关系
- Tk 需在 Tj 完成后进行（如有）
- 说明哪些任务可以并行执行
```

## 执行步骤
1. **加载前置**：`sdd_read_artifact({ featureId })`，同时拿到 specify 与 plan。
2. **拆解任务**：优先按"文件级"或"接口级"划分；单条任务应能在一次编辑或一次运行内完成。
3. **写入产物**：`sdd_write_artifact({ featureId, phase: 'tasks', content })`。
4. **收尾**：告知用户可审阅任务清单；批准后进入 implement 阶段。

## 规则
- 每条任务必须包含"输入 / 产出 / 验收" 三要素，否则不合规
- 若某条任务的验收方式是手工检查，明确写出"检查什么"
- 不要在任务清单里塞入产品需求或架构决策，那是 specify/plan 的责任
